## Environment-variable reference

| Variable | Where used | Required in prod | Notes |
|---|---|---|---|
| `DATABASE_URL` | Backend | Yes | Full psycopg v3 DSN: `postgresql+psycopg://user:pass@host:5432/db` |
| `JWT_SECRET` | Backend | Yes | Min 32 chars; must NOT be `changeme`; app refuses to start without it |
| `VAULT_KEY` | Backend | Yes | 32-byte URL-safe base64; must NOT be the committed dev default |
| `ALLOWED_ORIGINS` | Backend | Yes | Comma-separated list of frontend origins, e.g. `https://ayaz.vercel.app` |
| `ENVIRONMENT` | Backend | Yes | Set to `production`; triggers the insecure-default guard |
| `REDIS_URL` | Backend | Recommended | Required for Celery background jobs; default `redis://localhost:6379/0` |
| `NEXT_PUBLIC_API_BASE` | Frontend | Yes | Public URL of backend; **baked into the JS bundle at build time** |

Additional optional vars: `ANTHROPIC_API_KEY`, `BILLING_PROVIDER`, `IYZICO_*`, `STRIPE_*` — see `.env.prod.example`.

Generate strong secrets:
```bash
# JWT_SECRET (hex)
python -c "import secrets; print(secrets.token_hex(32))"

# VAULT_KEY (URL-safe base64, 32 bytes)
python -c "import base64, os; print(base64.urlsafe_b64encode(os.urandom(32)).decode())"
```

## Path A — Easiest free: Render (backend) + Vercel (frontend)

### 1. Deploy backend to Render

1. Push this repo to GitHub/GitLab.
2. Go to [dashboard.render.com](https://dashboard.render.com) → **New → Blueprint**.
3. Connect the repo. Render detects `render.yaml` and provisions:
   - A **Web Service** (`ayaz-backend`) built from `backend/Dockerfile`
   - A **Managed Postgres 16** (`ayaz-db`)
4. Once the service is created, open its **Environment** tab and set the
   variables marked `sync: false` in `render.yaml`:

   | Variable | Value |
   |---|---|
   | `VAULT_KEY` | Output of the base64 command above |
   | `ALLOWED_ORIGINS` | Your Vercel URL, e.g. `https://ayaz.vercel.app` (fill in after step 2 below) |
   | `REDIS_URL` | Upstash Redis free-tier URL (`rediss://...`) or leave blank to disable Celery |

5. `JWT_SECRET` is auto-generated by Render (`generateValue: true`).
6. `DATABASE_URL` is injected automatically from the managed Postgres.
7. The `preDeployCommand` (`alembic upgrade head`) runs automatically before
   each new deploy goes live.
8. Copy the backend URL (e.g. `https://ayaz-backend.onrender.com`).

**Optional seed:** open the Render shell tab and run:
```bash
python -m scripts.seed_demo
```

### 2. Deploy frontend to Vercel

1. Go to [vercel.com](https://vercel.com) → **Add New → Project** → import repo.
2. Set the **Root Directory** to `frontend`.
3. In **Environment Variables** add:

   | Variable | Value |
   |---|---|
   | `NEXT_PUBLIC_API_BASE` | Your Render backend URL, e.g. `https://ayaz-backend.onrender.com` |

4. Deploy. Vercel runs `npm run build` and bakes `NEXT_PUBLIC_API_BASE` into
   the bundle automatically.
5. Copy the Vercel URL (e.g. `https://ayaz.vercel.app`).

### 3. Wire CORS back to the backend

In Render → `ayaz-backend` → **Environment**, update:

```
ALLOWED_ORIGINS=https://ayaz.vercel.app
```

Trigger a redeploy (or Render redeploys on the next push).

The app is now live. Share the Vercel URL.

## Path B — Single VPS (docker compose)

### Prerequisites

- A VPS with Docker + Docker Compose v2 installed.
- Ports 80/443 open (put a reverse proxy like Caddy or nginx in front;
  the compose file binds backend to 8000 and frontend to 3000 by default).

### Steps

1. Clone the repo onto the VPS:
   ```bash
   git clone <repo-url> /opt/ayaz
   cd /opt/ayaz
   ```

2. Create the env file:
   ```bash
   cp .env.prod.example .env.prod
   $EDITOR .env.prod
   ```

   Minimum required values in `.env.prod`:

   | Variable | Notes |
   |---|---|
   | `POSTGRES_PASSWORD` | Any strong password |
   | `JWT_SECRET` | Min 32 chars, random hex |
   | `VAULT_KEY` | 32-byte URL-safe base64 |
   | `ALLOWED_ORIGINS` | Public URL of the frontend, e.g. `https://yourdomain.com` |
   | `NEXT_PUBLIC_API_BASE` | Public URL of the backend, e.g. `https://api.yourdomain.com` |

3. Build images and run migrations:
   ```bash
   docker compose -f docker-compose.prod.yml --env-file .env.prod build
   docker compose -f docker-compose.prod.yml --env-file .env.prod run --rm migrate
   ```

4. Start all services:
   ```bash
   docker compose -f docker-compose.prod.yml --env-file .env.prod up -d
   ```

5. (Optional) Seed demo data:
   ```bash
   docker compose -f docker-compose.prod.yml --env-file .env.prod \
     run --rm backend python -m scripts.seed_demo
   ```

6. Point your reverse proxy at `localhost:3000` (frontend) and
   `localhost:8000` (backend API).

The `migrate` service is a one-shot container that runs `alembic upgrade head`
and exits; the `backend` service has `depends_on: migrate: condition: service_completed_successfully`
so it only starts after migrations finish.

## Path C — Local development

See `docs/07-dev-setup.md` for the full local quick-start. The short version:

```bash
# 1. Start Postgres + Redis
docker compose up -d

# 2. Backend
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env        # edit DATABASE_URL / JWT_SECRET if needed
alembic upgrade head
python -m scripts.seed_demo  # optional demo data
uvicorn ayaz.main:app --reload

# 3. Frontend (new terminal)
cd frontend
npm install
cp .env.example .env.local  # NEXT_PUBLIC_API_BASE=http://localhost:8000
npm run dev
```

Open http://localhost:3000. Log in with `demo@ayaz.app` / `demo12345`.

## Migration reference

Run from inside the `backend/` directory (or via Docker):

```bash
# Apply all pending migrations
alembic upgrade head

# Generate a new migration after model changes
alembic revision --autogenerate -m "describe the change"

# Roll back one step
alembic downgrade -1
```

In Docker (VPS path):
```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod \
  run --rm migrate
```

## Production checklist

- [ ] `JWT_SECRET` is at least 32 random characters and not `changeme`
- [ ] `VAULT_KEY` is a fresh 32-byte base64 value (not the committed dev default)
- [ ] `ENVIRONMENT=production` is set (triggers the startup guard)
- [ ] `DEBUG=false`
- [ ] `ALLOWED_ORIGINS` contains only your actual frontend URL(s)
- [ ] Postgres password is strong and not the dev default
- [ ] `alembic upgrade head` has been run before starting the backend
- [ ] Docker images have been built locally at least once to catch OS-level issues
